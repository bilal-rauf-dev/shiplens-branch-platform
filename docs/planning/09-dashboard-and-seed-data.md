# 09 — Dashboard Specification, Seed Dataset and Expected Values (Gate 1)

> **Status of sample data (updated 2026-10-24):** the event page publishes **no sample data**, so this dataset **is** the sample data. It ships as CSV files in `sample_data/` (`cities.csv`, `branches.csv`, `users.csv`, `members.csv`, `applications.csv`, `collections.csv`, `transfers.csv`, `weekly_reports.csv`, `content.csv`) and is loaded by `manage.py import_sample_data sample_data/`. `seed_demo` is a thin wrapper around the same import (plus demo passwords from `DEMO_PASSWORD`), so there is one load path. The expected values in §4 go into the README. If official data is ever released, load it through the same importer with `--mapping config/sample_mapping.yaml` and add `T-DASH-SAMPLE`.
>
> CSV conventions: UTF-8, header row, ISO dates (`2026-10-08`), amounts with a dot decimal and no separators (`5250.50`), codes as natural keys (`branch_code`, `member_id`) instead of DB ids, timestamps in PKT with an offset (`2026-10-08T18:00:00+05:00`). Report audit history is generated by replaying transitions during import, so the audit chain stays valid.

## 1. Conventions

- **Timezone:** Asia/Karachi for all business dates. Collections carry a `collection_date` (DATE, no TZ). Member `joined_on`, application `created_at` → converted to PKT date.
- **Period:** a calendar month selected in the dashboard (`?period=2026-10`), default = current month. All-time KPIs are evaluated **as of** `as_of` (default now; tests pass a fixed date).
- **Reference period for judging/video:** **October 2026**, `as_of = 2026-10-31 23:00 PKT`.
- **Money:** Decimal, displayed with 2 decimals and thousands separators.
- **Empty months:** zero-filled; never omitted; charts show 0 bars, KPI tiles show `Rs 0.00` with an empty-state hint.
- **Voided collections:** excluded everywhere. **Closed branches:** included in historical sums (money they collected is real), excluded from "active" counts and compliance.

## 2. KPI definitions

| ID | KPI | Formula (SQL-ish) | Source | Visibility |
|---|---|---|---|---|
| K1 | Collected in period | `Σ amount WHERE voided_at IS NULL AND collection_date IN period` (+ count) | collections | SA, FR (all); BL (own branch) |
| K2 | Approved in period | `Σ l.amount FROM weekly_report_lines l JOIN weekly_reports r WHERE r.status='LOCKED' AND l.revision=r.revision AND l.collection_date IN period` | report lines | SA, FR; BL own |
| K3 | Awaiting approval in period | `K1 − K2` (collected but not yet in a locked report) | derived | SA, FR; BL own |
| K4 | Unsent to main account (all-time, as of) | `Σ amount, COUNT, MAX(as_of_date − collection_date) WHERE transfer_id IS NULL AND voided_at IS NULL` | collections | SA, FR; BL own |
| K5 | Branches by status | `COUNT GROUP BY status` | branches | SA, FR |
| K6 | Active members / new in period | `COUNT WHERE status='ACTIVE'`; `COUNT WHERE joined_on IN period` | members | SA, FR (counts only); BL/HR own |
| K7 | Pending applications / acceptance rate in period | `COUNT WHERE status='PENDING'`; `accepted/(accepted+declined)` where `decided_at` in period | applications | SA, FR (counts); HR own |
| K8 | Reports awaiting review / returned | `COUNT WHERE status IN (SUBMITTED, RESUBMITTED)`; `COUNT WHERE status='RETURNED'` | weekly_reports | SA, FR; BL own |
| K9 | Report compliance, last completed week | `#ACTIVE branches having report for week with status IN (SUBMITTED, RESUBMITTED, APPROVED, LOCKED) / #ACTIVE branches`; "last completed week" = Mon–Sun week ending before `as_of` | branches, reports | SA, FR |
| K10 | Sent to main account in period | `Σ total_amount FROM transfers WHERE transfer_date IN period` | transfers | SA, FR; BL own |
| TR1 | 12-month trend: collected vs approved | K1, K2 per month for the 12 months ending at period | — | SA, FR; BL own |
| TR2 | 12-month trend: new members | K6-new per month | — | SA, FR |
| L1 | Unsent collections list | rows of K4 sorted by age desc: branch code, ref, date, method, amount, age (days), lock state, report status of its week | collections | SA, FR; BL own |
| L2 | Per-branch table (period) | per branch: collected, approved, unsent, last report status | — | SA, FR |

Implementation: each KPI is a pure function in `apps/dashboard/kpis.py` taking `(period, as_of, branch_ids=None)` and returning plain Python values — easy to test and explain. No caching (REQ-094).

### 4.6 Edge cases covered
- **Locked but unsent:** C05 (in an approved report yet still not deposited) → appears in K4 and L1, counts in K2.
- **Returned report:** R8 → C06 counted in K1/K3, not K2.
- **Paused branch:** ISB → excluded from K9 denominator; its unsent C13 still in K4.
- **Closed branch:** QTA → excluded from K5 active and K9; its August history in TR1.
- **Voided entry:** C07 excluded from all totals and L1.
- **Week spanning months:** R6 (Sep 28 – Oct 4): only C09 (Oct 2) → counted in October by line date.
- **Month with no data:** Jul & Nov → zeros, acceptance "—".
- **Duplicate application:** APP-00008 flagged; counted once in pending.
