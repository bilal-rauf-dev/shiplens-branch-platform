## 2. Specific controls

| Topic | Decision |
|---|---|
| Sessions vs JWT | **Server-side sessions** (DB). Revocable instantly (deactivate user → `Session` purge), no token storage in JS, CSRF handled by Django. JWT adds complexity with no consumer. |
| Cookie flags | `SESSION_COOKIE_SECURE=True`, `HTTPONLY=True`, `SAMESITE='Lax'`, name `__Host-sid` (requires Secure, path `/`, no domain); CSRF cookie `__Host-csrftoken`, Secure, `CSRF_COOKIE_HTTPONLY=False` not needed since forms embed token → set True. |
| CSRF | Django `CsrfViewMiddleware`; every POST form uses `{% csrf_token %}`; no `csrf_exempt` anywhere (CI grep). |
| CORS | None needed (same-origin app). No `django-cors-headers`; browsers block cross-origin by default. |
| Rate limiting | Login: axes. Public form: 5/hour/IP + 20/day/IP. Exports: 30/hour/user. Health: none (cheap). |
| Validation & encoding | Forms whitelist; autoescape on; `|safe` used only on sanitised CMS HTML (one template tag, reviewed). |
| Mass assignment | `ModelForm.Meta.fields` explicit lists; status/branch/code/created_by never in forms; services set them. `T-SEC-MASS-ASSIGN` posts `status=APPROVED` to narrative form → ignored. |
| IDOR | All `get_object_or_404` calls take a scoped queryset; custom ruff/grep check that `Model.objects.get(` isn't used in views. |
| Secrets | Render env vars (`SECRET_KEY` generateValue, `DATABASE_URL` from DB, `DEMO_PASSWORD` set manually); `.env` gitignored; `.env.example` committed; `gitleaks` action in CI. |
| Demo credentials | Seeded only when `DEMO_MODE=true`; password from env (rotatable by changing env + redeploy → seed re-hashes); demo accounts can't change their password or be edited by other users; SA "Reset demo data" button re-runs seed; README warns that the live site is a demo with fictional data. Demo SA cannot create new SA accounts (prevents takeover persistence). |
| Public form spam | honeypot, min fill time (signed timestamp), rate limit, max lengths, no file uploads, no outbound email (no mail-bomb vector). |
| Applicant PII | Visible only to scoped HR + SA; never on public pages; not in Finance views; excluded from logs; exports audited; privacy notice page; retention note (declined applications purge after 12 months — documented, command `purge_declined_applications` OPT). |
| Errors | `DEBUG=False`; 400/403/404/500 templates localised; 403 page doesn't reveal resource existence. |
| File uploads | None in MVP (CMS images chosen from bundled assets) → removes a whole attack class. |
| Backups | Render paid Postgres has daily backups; free tier none → document `pg_dump` via `render psql`/local before judging; handover guide includes restore steps. |
| Headers (CSP) | `default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; font-src 'self'; connect-src 'self'; frame-ancestors 'none'; form-action 'self'; base-uri 'self'; object-src 'none'` |

## 3. Threat model (STRIDE-lite)

| Threat | Asset | Mitigation |
|---|---|---|
| Branch Lead inflates/deflates past figures | collections, reports | 7-day lock, week-closed rule, snapshots, audit |
| Finance approves own fabricated numbers | reports | FR can't create/edit collections |
| Insider deletes evidence | audit | append-only triggers, hash chain |
| Credential stuffing on staff login | accounts | axes lockout, Argon2, generic errors, login POST limits of 20/minute and 200/day per resolved client IP across all emails (H-05) |
| Bot floods application form | DB, HR time | honeypot, timing, rate limits |
| XSS via CMS or applicant motivation | users' sessions | escaping, nh3, CSP |
| Enumeration of applicants/members | PII | identical responses, 404 for out-of-scope |
| Public demo vandalism | demo data | no hard deletes, demo reset button, demo-account protections |

## 4. Audit design

### 4.1 Event taxonomy (`<entity>.<verb>`)

| Domain | Events |
|---|---|
| auth | `auth.login_succeeded`, `auth.login_failed`, `auth.locked_out`, `auth.rate_limited`, `auth.logout`, `auth.password_changed`, `auth.password_reset_issued` |

| user | `user.created`, `user.updated`, `user.deactivated`, `user.reactivated`, `assignment.added`, `assignment.removed` |
| settings | `settings.updated`, `demo.reset` |
| branch | `branch.created`, `branch.updated`, `branch.activated`, `branch.paused`, `branch.resumed`, `branch.closed`, `city.created` |
| application | `application.submitted`, `application.reassigned`, `application.accepted`, `application.declined`, `application.spam_blocked` (no PII) |
| member | `member.created`, `member.updated`, `member.status_changed`, `member.reinstated`, `team.created`, `team.updated`, `volunteer_role.created`, `volunteer_role.updated` |
| collection | `collection.created`, `collection.updated`, `collection.voided`, `collection.adjusted`, `collection.edit_denied`, `collection.sent`, `transfer.created` |

### 4.2 Captured fields
See `08-data-model.md` §3.16: actor id/label/role, occurred_at (UTC), action, entity type/id/label, branch id, before/after (changed fields only), metadata, IP, user agent, request id, prev_hash, hash.

### 4.3 Capture mechanics
- `audit.record(actor, action, entity, before=None, after=None, metadata=None)` reads IP/UA/request-id from a `contextvars` request context set by middleware (system/command context → `actor_label="system"`).
- Called only inside `transaction.atomic()` blocks in services (assert `connection.in_atomic_block`).
- `diff(before_dict, after_dict)` helper stores only changed fields; redacts `password`, `*_token`, `secret*`.
- Auth events via Django signals `user_logged_in`, `user_logged_out`, `user_login_failed` and axes `user_locked_out`.

### 4.4 Guaranteeing "every change"
1. Architecture: all writes go through services; views never call `.save()` on domain models (code review + grep check in CI: `\.save\(` forbidden in `views.py`).
2. Test `T-AUD-COVERAGE`: for each mutating route in the route registry (POST routes), perform a valid request as an allowed role and assert `audit_log` count increased with the expected action.
3. DB: no admin, no shell on Render free tier.

### 4.5 Viewer UI (Super Admin)
Filters: date range, actor, role, action (grouped), entity type, entity id/label search, branch. Table: time (PKT), actor, action badge, entity link, summary. Detail drawer: before/after diff table, IP, UA, request id, hash. Buttons: Export CSV (audited), Verify chain. Pagination 50/page, newest first; index-backed.
Per-entity "History" panel on branch/member/collection/report/content detail pages.

P5 implements the global viewer at `/<lang>/app/audit/` and event detail at
`/<lang>/app/audit/<id>/`, restricted to Super Admin. GET filters include inclusive
Karachi dates, captured actor email and role, recorded action (grouped by prefix),
entity type, entity ID or label, and branch. Pages contain 50 events, ordered by
time and ID descending, and retain filters in pagination links. Entity links are
checked against the central permissions and scoped querysets; unknown or missing
records remain plain text. Structured before/after values are escaped JSON.

The POST-only verification service takes the existing audit-chain advisory lock,
runs `verify_chain()` and counts the same stable chain, then records
`audit.chain_verified` with its result. The displayed count excludes this new
verification event. A broken chain is reported, never repaired or hidden. Existing
time, actor FK, action, entity/time and branch/time indexes cover the required
columns; no duplicate index or migration is added. Audit rows have no edit/delete
views or services. CSV export is not part of this step.
